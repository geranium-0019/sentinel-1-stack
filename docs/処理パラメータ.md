# ISCE2処理パラメータの決め方

[作業全体の流れ](ISCE2処理の流れ.md) → **このページで条件を決める** → [操作マニュアルのprepare](操作マニュアル.md#11-isce2の処理スクリプトを生成する) の順に進めます。
編集するのはプロジェクトのYAMLです。同じ `processing:` などを追加せず、既存の項目を書き換えてください。

## 最初はここだけ決める

**まずbbox・基準日・DEMを設定し、残りは設定例を出発点にします。** 次に、細部を優先するか、計算負荷を抑えるかでlooksを決めます。
以下の「おすすめ」はこのツールで初回処理を進めるための出発点であり、地域ごとの最適値や精度保証ではありません。「初期値」は [example.yaml](../config/example.yaml) の値です。

| 決めるもの | 最初のおすすめ | 変更する場面 |
|---|---|---|
| `paths.dem` | dem成功時に自動設定される相対パスを確認 | 別のDEMを使うとき |
| `processing.bbox` | 対象と周辺の安定した陸域が入る範囲 | 対象が欠ける、位置合わせ用の陸域が少ないとき |
| `processing.reference_date` | 取得済みのうち期間中央付近の良好な観測 | 欠損や範囲不足があるとき |
| `processing.swaths` | `null`で自動選択 | 対象の帯を意図的に限定するとき |
| `range_looks` / `azimuth_looks` | 初回の全体確認は `9` / `3`。細部重視なら `3` / `1` を比較 | 小さい構造が潰れる、ノイズや計算負荷が大きいとき |
| `pairs.connections` | 動作確認は `1`。時系列解析用の比較候補は `2` | ペアの冗長性が不足するとき |
| 位置合わせ・アンラップ | `NESD`・`unwrap: true`・`snaphu` | ログと結果を調べて方式を比較するとき |
| 並列数 | `1`から開始 | 実行時のメモリに余裕があるとき |

**それ以外は、最初から変更する必要はありません。** 以下は迷った項目だけ読めるよう、設定の役割ごとにまとめています。本ツールの対応範囲と入力制約は [prepare.py](../src/sentinel_1_stack/prepare.py) に実装されています。ISCE2本体の全オプションをYAMLから指定できるわけではありません。

## 1. 入力と処理範囲

### `workflow`・`polarization`

| 項目 | 指定できる値・初期値 | 意味とおすすめ |
|---|---|---|
| `workflow` | `interferogram`のみ | 位置合わせしたSLCから干渉画像を作る処理。本ツールでは変更しません |
| `polarization` | `vv`（初期値）、`vh`、`hh`、`hv` | 処理する偏波。入力に実際に含まれる偏波を選びます。VV/VHのデータで地表変位を調べる初回は `vv` を出発点にします |

値は小文字で指定します。YAMLで `hh` と書いても、VV/VHの入力からHH画像を作ることはできません。

### `bbox` — どこを処理するか

`[南端, 北端, 西端, 東端]` の順の緯度・経度です。単位は度で、南緯・西経は負の数です。初期値 `null` は準備用で、**prepare前に設定が必要**です。

```yaml
  bbox: [-8.50, -8.20, 115.36, 115.64]  # Agungの例。他地域では変更する
```

範囲を広げると周囲の情報を使えますが、時間・容量・メモリが増えます。狭めると軽くなる一方、位置合わせや結果評価に使える陸域が減ります。まず対象と周辺の安定した陸域を含め、入力SLC・DEMの範囲内に収めてください。海だけを増やしても有効な位相情報は増えません。

この指定は処理対象を決めるもので、全中間ファイルを厳密にこの長方形の寸法へ切り抜く指定ではありません。バースト単位の中間処理もあります。

### `swaths` — IW1・IW2・IW3のどれを使うか

**おすすめは `null`（自動）。** 項目を省略しても自動です。手動では `[3]`、`[2, 3]`、`[1, 2, 3]` のように1〜3の重複しないリストを指定します。

自動選択は、全SLCのZIP／SAFE内の指定偏波の位置情報から、bboxに重なる帯を調べます。複数の帯にまたがれば複数選択します。画像本体の展開や通信は行いません。結果は画面と `logs/prepare.json` に記録し、元のYAMLは変更しません。`prepare --dry-run` でも確認できます。

bboxの範囲不足・annotation不足・観測日間の選択結果の違いがあると停止します。位置情報の外周による事前判定で、バースト内の全画素の品質まで保証するものではありません。日付変更線をまたぐ画像は自動判定に未対応です。明示指定したリストはそのまま使用します。

> 自動選択はrc4公開後の追加機能です。配布済み `0.1.0-rc4` には含まれません。今回のPCでは `sentinel-1-stack:0.1.0-rc4-swaths` を使います。

### `reference_date` — 位置合わせの基準日

取得済みの観測日を文字列 `"YYYYMMDD"` で指定します。初期値は `null` で、prepare前に指定が必要です。

**期間中央付近の、対象を十分カバーする良好な観測を候補にします。** 中央なら必ず最良という意味ではなく、欠損バーストやデータ品質も確認します。

これは全SLCの座標をそろえる先です。全干渉画像をこの日とのペアにする指定でも、変位を0と置く地上基準点でもありません。

### `paths.dem`・作業パス

`paths.dem` はdem成功時に **WGS84楕円体高のDEM** の相対パスへ自動更新されます（rc4公開後の追加機能。配布済みrc4では手動設定）。DEM本体に加えて `.xml`・`.vrt` が必要です。prepareで範囲と高さの基準を確認します。

`work_dir` が作業全体のルートで、相対指定ならYAMLの置き場所が基準です。`config/` 内のYAMLから `work_dir: ..` とすれば、その親が作業ルートになります。`paths.slc`・`orbit`・`aux`・`processing`・`output`・`logs` は作業ルート内の保存先です。初回は設定例のまま使うと、操作マニュアルと対応を取りやすくなります。

## 2. 位置合わせ — 普段は初期値のまま

### `coregistration`

| 値 | 意味 | 選ぶ場面 |
|---|---|---|
| `NESD`（初期値・おすすめ） | 軌道・DEMによる位置合わせに、バースト重複部から推定する補正を加える | 通常のIW干渉処理 |
| `geometry` | 幾何情報による位置合わせを使い、NESD補正を使わない | NESDが成立しない理由を確認し、補正なしの結果を評価するとき |

`geometry` は「NESDより粗くても必ず成功するモード」ではありません。エラーを消すためだけに切り替えず、残る位置ずれと位相への影響を確認します。本ツールは自動で切り替えません。方式の意味は [ISCE2のstackSentinel.py](https://github.com/isce-framework/isce2/blob/b7702cfbd571681a133ebc5c3b23a10c78d52706/contrib/stack/topsStack/stackSentinel.py) に対応しています。

### 位置ずれ推定の3項目

| 項目 | 指定範囲／初期値 | 大きく・小さくすると | 最初のおすすめ |
|---|---|---|---|
| `esd_coherence_threshold` | 0より大きく1未満／`0.85` | 高いと位相の整合性が高い画素に絞るが、使える画素が減る。低いと画素は増えるが不安定な推定を混ぜる可能性がある | まず `0.85`。有効画素不足ならログを確認して `0.7` などと比較 |
| `snr_misreg_threshold` | 有限の0以上の数／`10.0` | レンジ方向の相互相関による位置ずれ推定を採用するSNRの基準。高いほど厳しく、低いほど弱い相関も採用する | `10.0` のまま。推定値と採用数を確認してから調整 |
| `num_overlap_connections` | 1以上の整数／`3` | NESD用に各観測を後続何観測と接続するか。増やすと推定用の組み合わせ・計算量が増えるが、長い間隔の組み合わせが必ず役立つとは限らない | `3` のまま開始 |

**ESDの閾値は最終コヒーレンス画像をマスクする閾値ではありません。** SNR閾値も0〜1のコヒーレンスとは別の指標です。`num_overlap_connections` は位置合わせ用で、次節の最終干渉ペア数とは独立です。

有効画素不足で止まったら、まず重複部に十分な陸域があるか、コヒーレンスと採用画素数を確認します。その後、bbox・ESD閾値・接続数を一つずつ比較してください。複数条件を同時に変えると改善理由が分かりにくくなります。

## 3. 干渉ペア — `pairs.connections`

**1以上の整数**で、日付順で各観測を後続の何観測と組み合わせるかを指定します。初期値は `1` です。`all` という文字列は本ツールでは受け付けません。

| 設定 | A・B・C・Dの4観測で生成するペア | おすすめの使い方 |
|---|---|---|
| `1` | A–B、B–C、C–D | 初回の動作確認、時間・容量を抑える |
| `2` | A–B、A–C、B–C、B–D、C–D | 時系列解析用に冗長性を増やす比較候補 |
| `3` | 上記にA–Dを追加 | 長めの間隔でもコヒーレンスが保たれるか調べる |

「2」は2日後ではなく、後続2観測です。6観測なら `1` で5ペア、`2` で9ペア、16観測なら15ペア・29ペアです。

増やすと干渉画像・アンラップの処理量と容量が増えます。長い間隔ではコヒーレンスが下がる場合もあります。`1` の鎖状の接続では一つの不良ペアが時系列全体の接続に影響しやすいため、時系列解析では `2` などを候補に、実際の品質と接続を確認します。

この指定は時間順の接続で、空間基線を閾値で選別する設定ではありません。値を増やすだけでSBASの解析品質が保証されるわけではありません。

## 4. 細部とノイズ — looks・filter

### `range_looks` / `azimuth_looks`

どちらも **1以上の整数**です。レンジ方向と衛星進行方向に、複数画素をまとめる数を指定します。`9×3` は9m×3mという意味ではありません。

| 値の組み合わせ | 得失 | おすすめの場面 |
|---|---|---|
| `9` / `3`（初期値） | 細部を平均化する一方、出力画素数と後段の負荷を抑えられる | 初回の全体確認 |
| `3` / `1` | 細部を残しやすい一方、ノイズ・メモリ・容量に注意が必要 | 小さい火山や局所的な位相変化を調べる比較条件 |
| `1` / `1` | マルチルックによる画素の集約を行わない。後段の負荷が大きい | 明確な目的と十分な資源がある場合 |

同じ範囲なら `3×1` の干渉画像の画素数は `9×3` のおおむね9倍です。ただし処理全体の時間・容量が一律9倍になるわけではありません。元の画素間隔は方向で異なるため、数字が同じでも地上で正方形の画素になるとは限りません。

### `filter_strength`

**0〜1、初期値 `0.5`。まず `0.5` をおすすめします。** 干渉位相のフィルタの強さです。一般に高い値ほど平滑化が強まり、ノイズを抑える一方で局所的な変化にも影響します。

細部への影響が気になるときは、同じlooksで弱めの条件（例 `0.3`）と比較します。アンラップが難しいからといって強くすれば解決するとは限りません。未フィルタ位相・フィルタ後位相・コヒーレンスを合わせて見ます。

**looksで失った細部は、filterを弱めたりGeoTIFFの画素間隔を細かくしたりしても復元しません。**

## 5. アンラップと保存方式

| 項目 | 選択肢・初期値 | 何を変えるか／おすすめ |
|---|---|---|
| `unwrap` | `true`（初期値・省略時）、`false` | `true` はアンラップまで実行。折り返し位相だけが必要な場合に限って `false` |
| `unwrap_method` | `snaphu`（初期値）、`icu` | アンラップ方式。まず `snaphu`。`icu` は結果を比較したい場合に使い、メモリ不足の万能な対処として選ばない |
| `remove_filter_effect` | `false`（初期値）、`true` | `true` はフィルタの影響を取り除いた追加アンラップ出力を作る。通常は `false`。フィルタなしでアンラップをやり直す意味ではない |
| `virtual_merge` | `true`（初期値）、`false` | `true` は結合SLC・幾何情報に仮想ファイルを使って実体の重複保存を抑える。通常は `true`。実体ファイルが必要な用途では `false` を検討 |

仮想ファイルは参照先のバーストデータに依存します。結合ファイルだけをコピーしたり、参照元を先に削除したりすると読み込めなくなります。`virtual_merge: true` でも全中間ファイルの容量がなくなるわけではありません。

アンラップは位相の2πの折り返しをつなぎ直す処理です。実行成功だけで変位の正しさは判断できません。低コヒーレンスの海を挟む島どうしなどでは、別々の連結成分になり、相対的な位相オフセットが決まらないことがあります。

**本ツールのYAMLには、出力画像を任意のコヒーレンス閾値で一律マスクする項目や、SNAPHU内部の全設定はありません。** 最終解析のマスクは後段で決めます。ISCE2の方式・追加出力の定義は [上流のオプション定義](https://github.com/isce-framework/isce2/blob/b7702cfbd571681a133ebc5c3b23a10c78d52706/contrib/stack/topsStack/stackSentinel.py#L147-L175) を参照してください。

## 6. 速度とメモリ — 並列数

| 項目 | 指定範囲／初期値 | 役割 |
|---|---|---|
| `execution.num_processes` | 1以上の整数／`1` | 各工程の独立したコマンドの並列数 |
| `execution.num_processes_topo` | 1以上の整数／`1` | topo処理用の並列数。通常の工程とは別に指定 |
| CLIの `--unwrap-jobs` | 1以上の整数／`1` | run実行時のアンラップ同時実行数の上限。YAMLの項目ではない |

**最初はすべて1。** 処理中のRAM・スワップを見て余裕があれば2を試します。CPUのコア数だけで決めないでください。並列数を増やすとメモリ不足で、かえって遅くなったり停止したりする場合があります。これらは独立した設定で、単純な積が常時動くプロセス数になるわけではありません。

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" run "$CONFIG" --resume --unwrap-jobs 1
```

これは中断した処理を再開し、アンラップを最大1件ずつ実行する例です。上限を大きくしても、生成済みrun_filesの待機境界を越えて同時実行はしません。終了コード `-9` は強制終了を表し、メモリ不足の可能性がありますが、それだけでは原因を確定できません。

## 7. GeoTIFFの出力 — `export`

アンラップ結果もGeoTIFFに出す場合は、アンラップ完了後、exportコマンドに `--include-unwrapped` を付けます。`unwrap: true` だけではexportの追加出力指定にはなりません。

| 項目 | 指定範囲／初期値 | おすすめと注意 |
|---|---|---|
| `pixel_size_degrees` | 正の有限値／`0.0001` | まず初期値。地図グリッドの間隔で、単位は度。緯度方向では約11m、経度方向は緯度で変わる |
| `resampling` | `bilinear`（初期値）、`near` | まず `bilinear`。周辺画素から補間する。`near` は最近傍の値を使いたいとき |

細かいグリッドはファイルを大きくしますが、観測の分解能を高めません。本ツールでは折り返し位相をそのまま平均せず、正弦・余弦を補間して位相に戻します。補間による見え方の違いもあるため、比較する出力では同じ条件にそろえます。実装は [export.py](../src/sentinel_1_stack/export.py) を参照してください。

## 8. 設定変更後にどこからやり直すか

| 変えた設定 | 次にすること |
|---|---|
| bbox・基準日・swaths・位置合わせ・looks・filter・ペア・アンラップ方式・生成時の並列数 | 既存の処理と対応ログを退避し、prepareから再生成する |
| `processing.unwrap` のtrue／falseだけ | 再生成不要。falseからtrueに変えて `run --resume` すると未完了のアンラップを実行する |
| runの `--unwrap-jobs` | 生成し直さず、上の再開コマンドで上限を指定する |
| exportのグリッド間隔・補間方法 | ISCE2処理は再実行せず、既存の出力を退避してexportを再実行する |

**unwrapの実施切替を除き、生成済みの処理条件はYAMLの編集だけでは更新されません。** 設定を変えた処理に古い完了記録を使って `--resume` しないでください。bboxを広げる場合はDEMとSLCの範囲も再確認します。具体的な退避手順は [設定変更とNESDエラー](reference.md#位置合わせの設定とnesdエラー) を参照してください。

取得時の `--jobs`・`--retries`・`--allow-restituted`・`--fill-missing-zero` などは、ここで扱った処理パラメータとは別のCLIオプションです。[操作マニュアル](操作マニュアル.md) の各取得手順を参照してください。
