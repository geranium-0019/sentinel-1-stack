# 補助ツール：準備済み設定から一括実行する

個別の工程を確認しながら進める [操作マニュアル](操作マニュアル.md) が通常の使い方です。
この補助ツールは、処理条件が決まっていて、データ取得から解析・GeoTIFF出力まで続けて実行したい場合に使います。

## 事前に用意するもの

- Dockerが動く環境と、このツールの最新版の操作用ファイル。
- 読み込み済みのイメージ、またはダウンロード・チェックサム確認済みのイメージtar／tar.gz。
- 作業場所を指定したYAML。対象サブスワス・bbox・基準日・ペア接続数・looks等を設定済みにする。
- 設定YAMLと同じディレクトリにASFのJSON／GeoJSONを1件。複数ある場合は `--json` で指定する。
- Earthdata認証（`~/.netrc`、または `EARTHDATA_NETRC`）と十分な空き容量。

SLC・軌道・DEMは未取得でも構いません。DEMを自動取得する場合、`paths.dem` は `null` のままにします。
既存DEMを使う場合は `paths.dem` に設定します。その場合、DEM取得は省略し、prepareで入力を検査します。
研究上の判断が必要なbbox・基準日などを自動決定するツールではありません。

## まず実行計画を見る

以下では、通常の操作手順で設定した `TOOL_DIR`・`CONFIG`・`IMAGE` を使います。

```bash
"$TOOL_DIR/scripts/batch.sh" "$CONFIG" --image "$IMAGE" --plan
```

`--plan` はコマンドの流れだけを表示します。Dockerやネットワークを使用せず、ファイルも作りません。
入力の中身が適切か、処理できるかまでは検証しません。

## 一括実行する

イメージを既に読み込んでいる場合：

```bash
"$TOOL_DIR/scripts/batch.sh" "$CONFIG" --image "$IMAGE"
```

イメージの読み込みも含める場合：

```bash
"$TOOL_DIR/scripts/batch.sh" "$CONFIG" --image "$IMAGE" \
  --image-archive /path/to/sentinel-1-stack-0.1.0-rc3-linux-amd64.tar.gz
```

`/path/to/…` は実際に保存したファイルへ置き換えます。イメージ自体のダウンロードやソースの展開は行いません。
`--image-archive` を指定すると `docker load` を行い、指定したイメージが存在することを確認します。
その後の工程は確認したイメージIDに固定して実行します。

実行順序は次のとおりです。

1. イメージ確認・必要なら読み込み、YAMLの処理パラメータの検査。
2. `init` で作業ディレクトリ構成を作成。
3. `download` でSLCを取得。
4. `orbit` で軌道ファイルを取得。
5. `paths.dem` が未設定なら `dem` でDEMを取得。
6. 使用するDEMと作業ルートを反映した、今回の一括実行用YAMLを作成。
7. `prepare --dry-run` → `prepare`。
8. `run`。
9. `export`。YAMLの `unwrap` がtrueなら `--include-unwrapped` を追加。

**元のYAMLは変更しません。** 一括実行用のコピーは `作業ルート/config/batch_日時_ID.yaml` に保存します。
これはJSON形式で記述した有効なYAMLです。今回使用した設定として保存し、解析再開時にも使います。
取得したDEMの指定には、その呼び出しが出力した成功記録を使います。既存フォルダから推測で選びません。

処理全体のログは、YAMLで指定したログディレクトリの `batch_日時_ID.log` に保存します。
工程ごとの通常ログも残ります。イメージ読み込みやYAML検査の段階で失敗し、作業場所を確定できなかった場合は、表示される一時ログのパスを確認してください。
同じ作業場所でこの一括ツールを同時実行すると停止します。別ターミナルから個別コマンドを並行実行しないでください。

## 追加オプション

| オプション | 用途 |
|---|---|
| `--download-jobs 2` | SLCの同時取得数（既定1、rc3以降） |
| `--json /path/to/results.geojson` | ASF JSONを明示指定 |
| `--allow-restituted` | 精密軌道がない場合に速報軌道を許可 |
| `--fill-missing-zero` | DEMの未配布タイル・欠損画素を0m（EGM96高）で補完することを明示的に許可 |
| `--unwrap-jobs 1` | アンラップの同時実行数。既定1 |
| `--resume` | 入力取得とprepareを省略し、解析を再開 |

速報軌道やDEM補完は、指定なしで自動的に許可することはありません。

## エラー・中断後

最初のエラーで停止し、それ以降の工程は実行しません。既存の処理内容や出力を自動削除しません。

**取得中に停止した場合：** 原因を解消して、元のコマンドを再実行します。
正常な取得済みSLCは検証後にスキップされます。設定コピーが作られる前なら、元のYAMLを使います。

**解析中に停止した場合：** 表示された一括実行用YAMLを使い、`--resume` を指定します。
再開コマンドはログにも記録されます。

```bash
"$TOOL_DIR/scripts/batch.sh" /path/to/agung/config/batch_日時_ID.yaml \
  --image "$IMAGE" --resume
```

入力・設定・生成済みスクリプトを変更しないことが前提です。`prepare` 自体が失敗した場合や設定を変更した場合は、
[通常の再生成手順](reference.md#位置合わせの設定とnesdエラー) に戻ってください。
既存の `processing/` が空でない状態では、新規一括実行は取得前に停止します。

exportだけが失敗した場合は、ログで原因を確認して個別の `export` を実行できます。
既存のGeoTIFFを上書きする機能はありません。

この補助ツールの追加時には、工程の順序・異常停止・設定コピー・再開を模擬テストで確認しています。
一括コマンドそのもので実データを取得し、全解析を完走する検証はまだ行っていません。
