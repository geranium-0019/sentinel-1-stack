# Sentinel-1 スタック処理 操作マニュアル

[導入手順](distribution.md) が完了したところから、データ取得・解析・結果確認まで進めます。
ここでは **インドネシアのAgung火山を研究対象** にします。別の地域では保存先の名前や処理範囲を置き換えてください。
各段階の出力を確認してから次へ進みます。

導入手順で用意した操作用ファイルを使い、同じターミナルで続けます。
`TOOL_DIR` と `IMAGE` は導入手順で設定済みです。新しいターミナルの場合は、末尾の「作業を再開する場合」を参照してください。

作業全体の流れは [ISCE2処理の流れ](ISCE2処理の流れ.md)、設定の考え方は [処理パラメータ](処理パラメータ.md) を参照してください。

## 1. 作業ディレクトリを決める

今回は外部ストレージを使い、研究対象の名前 `agung` を作業ディレクトリ名にします。
ここに設定・取得データ・処理途中のファイル・結果をまとめます。

**`/mnt/ssd/agung` は例です。ご自身の保存先に変更してください。**
外部ストレージを使う場合は、使用するディスクがその場所に接続されていることを確認します。
ツール本体の展開先とは別に用意します。

```bash
WORK_DIR="/mnt/ssd/agung"
mkdir -p "$WORK_DIR"
```

## 2. configを作り、設定ファイルをコピーする

```bash
mkdir -p "$WORK_DIR/config"
cp -n "$TOOL_DIR/config/example.yaml" "$WORK_DIR/config/agung.yaml"
CONFIG="$WORK_DIR/config/agung.yaml"
```

**`agung.yaml` は自由に変更できるファイル名です。** 変更する場合は、コピー先と `CONFIG` の両方を同じ名前にします。
`cp -n` は同名ファイルがある場合に上書きしません。既存の設定を使う場合はその内容を確認してください。

## 3. ASFの検索結果をconfigに保存する

ASFで対象のSentinel-1 IW SLCを検索し、結果の `.geojson` または `.json` を **`$WORK_DIR/config/` に直接保存** します。
ブラウザから保存先を選ぶか、ファイルマネージャーでコピーしてください。これは取得対象の一覧で、SLC本体ではありません。

ファイル名はASFが付けた名前のままで構いません。次の名前も例です。

```text
agung/
└── config/
    ├── agung.yaml
    └── asf-datapool-results.geojson
```

`download` は設定YAMLと同じディレクトリにある `.json`／`.geojson` を探します。
**1件だけなら自動選択**し、選んだパスを表示します。サブディレクトリは検索しません。
0件または複数件なら停止し、対象ファイルを明示指定する方法を案内します。

## 4. 作業ディレクトリの設定を確認する

コピーした設定例の先頭は、あらかじめ次の設定です。

```yaml
work_dir: ..
```

`..` は **YAMLを置いた `config/` の一つ上** を意味します。今回なら `/mnt/ssd/agung` です。
この配置なら編集不要です。ターミナルの現在地を基準にする指定ではありません。
既存のYAMLを再利用する場合は、その `work_dir` が今回の保存先になっているか確認してください。

`paths.dem`、`processing.swaths`、`processing.bbox`、`processing.reference_date` は、まだ `null` のままで構いません。
入力データの取得後、手順10で設定します。

## 5. 処理用のディレクトリ構成を作る

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" init "$CONFIG"
```

表示された作業ルートが、手順1で決めた場所と一致していることを確認します。
`init` はディレクトリを作るだけで、取得やISCE2処理は開始しません。
ASFファイル・設定ファイルの移動や書き換えも行いません。

```text
agung/
├── config/
│   ├── agung.yaml
│   └── asf-datapool-results-2026-09-20_02-44-14.geojson
├── input/
│   ├── slc/
│   ├── orbit/
│   ├── dem/
│   └── aux/
├── processing/
├── output/
└── logs/
```

同じ設定で `init` を再実行しても、既存データは削除しません。

## 6. SLCのダウンロード予定を確認する

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" download "$CONFIG" --dry-run
```

ここでは通信・ダウンロードは行いません。表示される次の内容を確認します。

- 保存先：ホストでは `agung/input/slc`、コンテナ内では `/work/input/slc`。
- 製品数・観測日：選んだ検索結果と一致しているか。
- 合計容量：保存先に余裕があるか。処理途中のファイルにも別途容量が必要です。

観測日・製品数・容量は、ご自身が保存した検索結果によって変わります。
ファイルがすでに存在していても、ここで表示する容量は検索結果全体の容量です。

JSONを明示指定する場合だけ、次のように `--json` を付けます。
`/path/to/results.geojson` は実際のファイルに置き換えてください。

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" download "$CONFIG" --json /path/to/results.geojson --dry-run
```

## 7. SLCをダウンロードする

Earthdataの認証情報をホストの `~/.netrc` に設定済みであることを確認します。
未設定の場合は [認証手順](reference.md#earthdata-認証を接続して実行) を参照してください。

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" download "$CONFIG"
```

複数ファイルを同時に取得する場合は `--jobs 2` を付けます（rc3以降）。省略時は1件ずつです。

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" download "$CONFIG" --jobs 2
```

まず2並列で試してください。回線・ディスクが上限に達している場合は速くなりません。
1件が再試行上限に達するか、回復不能なエラーになると新しい取得を止め、実行中の取得にも停止を指示します。通信応答待ちの終了に時間がかかる場合があります。
検証済みのZIPは残るため、同じコマンドで再実行できます。

ZIPは `input/slc/` に保存され、サイズとMD5の検証後に正式名になります。
ASFのJSONは `config/` に残ります。ログと実行記録は `logs/downloads/` に保存されます。

通信などで停止した場合は、表示された原因を確認してから同じコマンドで再実行します。
正常な取得済みZIPは検証後にスキップします。未完成の `.part` があれば、rc4以降はその続きからの取得を要求します。
サーバーが途中再開に対応しない場合は先頭から再取得します。途中切断・一時的な通信エラーは既定で追加3回まで自動再試行します。
回数を変える場合は `--retries 5`、自動再試行を無効にする場合は `--retries 0` を付けてください。
認証エラーや不正な範囲応答では停止します。完成時には既存部分を含む全体のサイズ・MD5を検証します。
全製品の取得が終わってから、次へ進んでください。

## 8. 軌道ファイルを取得する

取得済みSLCの観測日時に対応する軌道ファイルを取得します。ASFのJSONを再指定する必要はありません。

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" orbit "$CONFIG" --dry-run
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" orbit "$CONFIG"
```

この `--dry-run` は軌道の問い合わせのために通信します。ファイルは保存しません。
標準では精密軌道（POEORB）を使用し、`input/orbit/` に保存します。
未提供の場合は停止します。速報軌道を許可する操作は [軌道取得の説明](reference.md#軌道ファイルの取得) を参照してください。

## 9. DEMを取得・作成する

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" dem "$CONFIG" --dry-run
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" dem "$CONFIG"
```

取得済みSLC全体の範囲を読み取り、SRTM DEMを取得・結合し、WGS84楕円体高へ変換します。
ここで使う範囲は、後で指定する火山周辺の `bbox` とは別です。
`--dry-run` でも配布一覧への通信があります。

未配布タイルや欠損画素で停止したら、表示された範囲を確認してください。
0m補完は自動では行いません。[補完の説明](reference.md#未配布タイル欠損画素) を確認して判断します。

**完了時に表示されたDEMの相対パスを、設定の `paths.dem` に記入してください。**
YAMLは自動更新されません。既存の `paths` 内の `dem: null` を置き換えます。

## 10. 処理条件を決める

```bash
nano "$CONFIG"
```

既存の項目を編集します。同じ名前の `processing:` などを追加しないでください。
以下は、対象データと目的を確認してから決めます。

| 項目 | 設定する内容 |
|---|---|
| `paths.dem` | 手順9で表示されたDEMの相対パス |
| `processing.swaths` | 処理範囲を含むサブスワス番号のリスト |
| `processing.bbox` | `[南端, 北端, 西端, 東端]` の順の緯度・経度 |
| `processing.reference_date` | 取得済み観測から選ぶ基準日。例の書式は `"YYYYMMDD"` |
| `processing.range_looks` / `azimuth_looks` | 既定は9／3。目的に応じて決める |
| `processing.esd_coherence_threshold` | NESD位置合わせに使うコヒーレンスの閾値。出力画像のマスク閾値とは別 |
| `pairs.connections` | 日付順で各観測を後続何観測と接続するか。既定は1 |
| `processing.unwrap` | 標準は `true`。アンラップを省略する場合だけ `false` |

今回のAgungの範囲・サブスワス・基準日は、この段階で確認して設定します。
設定の意味と決め方は [処理パラメータ](処理パラメータ.md) を参照してください。
nanoでは `Ctrl+O` → `Enter` で保存し、`Ctrl+X` で終了します。

## 11. ISCE2の処理スクリプトを生成する

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" prepare "$CONFIG" --dry-run
```

入力・設定・生成予定のコマンドを確認します。エラーがあれば先に解消します。

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" prepare "$CONFIG"
```

`processing/run_files/` と `processing/configs/` などが作られます。
この段階ではISCE2の各工程はまだ実行しません。ログは `logs/prepare.log` です。
既存の処理内容は上書きしないため、再生成時は退避が必要です。

## 12. 処理を実行する

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" run "$CONFIG" --dry-run
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" run "$CONFIG"
```

各工程を順番に実行します。途中でエラーがあれば停止し、次の工程へは進みません。
標準ではアンラップまで行い、アンラップは1ペアずつ実行します。
終了時に「指定された全工程が完了しました。」と表示されることを確認します。

ログは `logs/run.log`、工程ごとのログも `logs/` 内にあります。
停止した場合は、端末に出たエラーとログのパスを控えてください。

設定や生成スクリプトを変えずに再開する場合：

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" run "$CONFIG" --resume
```

完了済みの工程をスキップします。失敗工程はその先頭からやり直します。
範囲・looks・接続数などを変更した場合は、単純に再開せず、
[設定変更時の説明](reference.md#位置合わせの設定とnesdエラー) に従って処理内容を退避・再生成します。

## 13. GeoTIFFと確認画像を作る

アンラップまで完了した場合：

```bash
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" export "$CONFIG" --include-unwrapped --dry-run
"$TOOL_DIR/scripts/run.sh" --image "$IMAGE" export "$CONFIG" --include-unwrapped
```

`output/geocoded/` に、ペアごとの次のファイルが作られます。

- `phase_raw.tif`：未フィルタのラップ位相。
- `phase_final.tif`：フィルタ後のラップ位相。
- `coherence.tif`：コヒーレンス。
- `phase_unwrapped.tif`：アンラップ位相（ラジアン）。
- `connected_components.tif`：アンラップの連結成分番号。
- `preview.png`：ラップ位相とコヒーレンスの確認画像。

`report.html` で各ペアの画像を確認できます。変位時系列の推定はMintPyなどで行う別工程です。
アンラップを省略した場合は `--include-unwrapped` を外して実行してください。
既存の `output/geocoded/` は上書きしません。再出力する場合は先に退避します。

## 困ったときに残す情報

問題が出たら、実行したコマンド、端末のエラー全文、表示されたログのパスを控えてください。
マニュアルの説明が分かりにくい場合は、手順番号と迷った箇所を教えてください。
認証ファイルの内容やパスワードを貼る必要はありません。

## 作業を再開する場合（新しいターミナル）

シェル変数は新しいターミナルへ引き継がれません。次のパスを **自分が導入・作業した場所** に置き換えて設定します。
以下はrc4の展開先を使う例です。最新版をGitで取得した場合は、その取得先を `TOOL_DIR` に指定します。
`sentinel-1-stack-test` など別の保存先を使った場合も、自分の配置に変更してください。

```bash
TOOL_DIR="$HOME/sentinel-1-stack/sentinel-1-stack-0.1.0-rc4"
IMAGE="sentinel-1-stack:0.1.0-rc4"
WORK_DIR="/mnt/ssd/agung"
CONFIG="$WORK_DIR/config/agung.yaml"
```

その後、まだ完了していない手順から進めます。展開・設定ファイルのコピー・完了済みの取得を最初からやり直す必要はありません。
