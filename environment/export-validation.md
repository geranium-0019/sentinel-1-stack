# GeoTIFF出力と品質確認（2026-09-17）

## 方式

- ISCE2で生成済みの fine.int / filt_fine.int / filt_fine.cor を使用する。
- merged/geom_reference のマルチルック済み lat/lon.rdr と入力の寸法一致を確認。
- 複素位相を単位ベクトルへ正規化し、実部・虚部とコヒーレンスを同時にGDALでジオコード。
- 位相は atan2 で復元。±π境界を角度の算術平均で壊さない。
- GeoTIFF は同じ EPSG:4326 / bbox / 幅高さ。NoDataはNaN。値0の位相・コヒーレンスは有効。
- 欠損複素値・非有限値・補間後の位相ベクトル相殺はNoData。
- GDAL GEOLOCATION は PIXEL_CENTER を明示。参考: https://gdal.org/en/stable/development/rfc/rfc4_geolocate.html
- 位相符号は上流 generateIgram.py の reference * conjugate(secondary) を保持。
- 現在のexportはラップ位相用。アンラップ結果とPGVそのものは対象外。

## 検証

- 合成座標格子で向き・画素中心・共通グリッド・既知の位相値が一致することを検証。
- 179°/-179°の補間が0°にならず±180°付近になることを検証。
- 位相0・コヒーレンス0が保存され、複素値0は欠損扱いになることを検証。
- GDAL一時ファイルを専用一時ディレクトリへ明示し、読み取り専用CWDでも動作。
- 初期テストの座標フィクスチャはNumPyのゼロストライド配列から連続配列へ変換してからGDALへ渡すよう修正。
- 全105テストが一度成功。以前の不規則な環境エラーの原因を解明したという意味ではない。
